# Lead-to-cash cycle — discipline du flux financement

## Définition

Le **lead-to-cash cycle** est la traduction financière du pipeline
canonique (concept 1 tour 6). Il trace le parcours d'un lead depuis
MQL jusqu'à l'encaissement cash de la facture, puis jusqu'au renewal
H730. C'est le **miroir Sales** de la doctrine CCC (cash-conversion-cycle
DSO+DIO-DPO) posée par Wonder Woman tour 6 (`wonder-woman-cash-conversion-cycle-dso-dpo-dio-doctrine.md`
F26).

L'asymétrie canonique : WW tient la **phase post-cash** (régler le
DSO fournisseur et le DIO stock), Sales tient la **phase pré-cash**
(générer le flux MQL→SQL→OPP→CW→invoice) et le **levier upstream**
(quantité et qualité du pipeline). Les deux Captains partagent la
**jonction OPP→CW** (transition Sales→Finance), où l'ARR signé
devient revenu reconnu F3 MRR discipline.

## 4 phases du cycle lead-to-cash

### Phase P1 — Pré-cash (MQL → SQL → OPP) ≤ 60j cumulés

| Sous-phase | Responsable | Outil canon | Durée cible |
|---|---|---|---|
| MQL → SQL | Superman Growth | Lead-scoring rule v.N (Cyborg CRM) | ≤ 7j |
| SQL → OPP | JohnJones Sales | Reformulation client + buyer-read | ≤ 30j |
| OPP qualifié | JohnJones Sales | Forecast DoctorStrange sizing | ≤ 23j |

**Total P1 cible** : 60 jours cumulés. La doctrine canonique
(`b2-council-arbitrage-rule.md` + Captain America squad lead pattern)
prescrit un audit par quarter pour vérifier que les 60j sont tenus.

### Phase P2 — Conversion (OPP → CW → invoice) ≤ 30j

| Sous-phase | Responsable | Outil canon | Durée cible |
|---|---|---|---|
| OPP → CW | JohnJones + Aquaman | Contrat signé + périmètre écrit | ≤ 14j |
| CW → invoice | WonderWoman Finance | Billing system | ≤ 7j |
| Invoice → encaissement | WonderWoman Finance | Payment collector | ≤ 9j |

**Total P2 cible** : 30 jours cumulés. Cette phase est la **jonction
Sales-Finance** critique. La discipline `wonder-woman-f3-mrr-growth-discipline-doctrine.md`
F3 pose MRR discipline > 10pct MoM — l'invoice ici alimente MRR live
sur Wonder Woman radar.

### Phase P3 — Cash-collection (CW → cash) ≤ 30j

Cette phase est principalement Wonder Woman (`wonder-woman-cash-conversion-cycle-dso-dpo-dio-doctrine.md`
F26 — DSO = days sales outstanding). Sales est Consulted sur les
cas où le paiement client est bloqué par une dispute scope (couplage
Aquaman `legal_hold` + `privilege_framework`).

**Total P3 cible** : 30 jours. Cette phase est hors-périmètre Sales
canonique ; mais le Captain JohnJones est **redevable** quand le
cash-block vient d'un défaut de reformulation-validée (vague
reformulation floue, scope mal cadré) — c'est un **abus de position
B2** analogue au closer-qui-discovery.

### Phase P4 — Post-cash (renewal) H730

Cette phase est principalement Captain JohnJones
(`johnjones-post-signature-doctrine-active-nps-expansion-churn-renewal.md`
concept 3 tour 6). Wonder Woman est Informed via F3 MRR (l'expansion
contribue au MRR reconnu).

SaaS où ARR/MQL ≥ $500 signale funnel équilibré.

## Anti-pièges

- **Ne pas confondre lead-to-cash avec conversion funnel** : le
  funnel agrège les **états pipeline** (concept 1 tour 6) ; le
  lead-to-cash agrège les **flux financiers**. Sans le funnel, le
  lead-to-cash est vide ; sans le lead-to-cash, le funnel n'a pas
  de valeur financière.
- **Ne pas mettre Sales A sur le cash (P3)** : Sales est redevable
  sur les défauts amont (reformulation floue, scope non-cadré),
  pas sur le cash lui-même. Mettre Sales A sur P3 = abus de
  position B2 symétrique au closer-qui-discovery.
- **Ne pas traiter P4 (renewal) comme un deal séparé** : le renewal
  est une **continuation** du même contrat, pas un nouveau CW. Le
  Captain JohnJones tient la relation ; le renewal flag est un état
  pipeline (concept 1), pas un état financier.
