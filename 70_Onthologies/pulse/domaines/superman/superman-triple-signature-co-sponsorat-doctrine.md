# Superman Growth — doctrine co-sponsorat triple-signature pour DoD attention cross-domaines

## Pourquoi cette doctrine existe

Les cas-types 2 (awareness prelaunch) et 3 (SEO long-terme) du DoD attention portent une **triple-signature** Superman + capitaine transverse + JohnJones :

- **Cas-type 2** (awareness) : Superman (Growth) + **People** (Green Lantern, brand voice co-signature) + **JohnJones** (Sales, qualification amont)
- **Cas-type 3** (SEO) : Superman (Growth) + **Flash** (Product, contenu + scope feature landing) + **JohnJones** (Sales, intent signal SQL)

Le cas-type 1 (US premium paid media) ne porte qu'une **double-signature** Superman + JohnJones — il n'a pas de capitaine transverse parce que le canal paid media ne touche ni la brand voice (People) ni le contenu produit (Flash). C'est la **différence structurelle** entre les 3 cas-types qui motive la formalisation.

**Doctrine unilatérale Superman** : tout DoD attention cross-domaine doit porter une triple-signature Superman + capitaine transverse + JohnJones. Superman pose cette doctrine dans son périmètre B2 (Accountable sur les pair-checks #5 Finance→Growth et #7 Legal→Growth, Consulted sur les autres transitions Growth-amont, cf. `b2-pair-check-raci-by-rank.md`).

## Les 3 niveaux de signature selon la complexité cross-domaine

| Niveau | Composition | Cas-type applicable | Critère déterminant |
|---|---|---|---|
| **Signature simple** | Superman seul | DoD 100% Growth (ex : post-mortem interne) | Pas de transition cross-domaine |
| **Double-signature** | Superman + JohnJones | DoD Growth → Sales (cas-type 1 paid media) | 1 transition cross-domaine (Growth → Sales) |
| **Triple-signature** | Superman + capitaine transverse + JohnJones | DoD Growth → transverse → Sales (cas-types 2 brand, 3 SEO) | 2 transitions cross-domaine (Growth → transverse ET Growth → Sales) |

**Règle de lecture** : un DoD attention touche **deux transitions** ssi la chaîne complète traverse un capitaine transverse **avant** de revenir vers JohnJones. C'est le cas des canaux qui produisent un livrable **intermédiaire** (brand recall, trafic SEO) qui doit ensuite être qualifié par Sales — le capitaine intermédiaire est **co-responsable** de la qualité du livrable, donc cosignataire.

## Les 5 capitaines transverses canoniques

La doctrine identifie **5 capitaines transverses** qui peuvent être cosignataires d'un DoD attention Superman :

1. **People (Green Lantern)** — brand voice (cas-type 2 awareness), brand narrative, ICP refinement. Superman = A voix + C dotation / Green Lantern = A dotation + C voix (cf. `brand-raci-asymmetry-canonique.md` doctrine double-A croisé).
2. **Flash (Product)** — contenu (cas-type 3 SEO), feature scope landing, productize messaging. Superman = C contenu + A distribution / Flash = A contenu + C distribution.
3. **Cyborg (IT)** — analytics stack, tracking instrumentation, tag management. Superman = A mesure + C implémentation / Cyborg = A implémentation + C mesure.
4. **Aquaman (Legal)** — claims publics, mentions légales, RGPD consents. Superman = A message + C conformité / Aquaman = A conformité + C message.
5. **Wonder Woman (Finance)** — budget paid media, ROI seuil, depreciation cycle. Superman = A canal + C ROI / Wonder Woman = A ROI + C canal (par symétrie avec triplet 58 extension).

**Note** : Wonder Woman comme cosignataire **d'un DoD** est distincte de Wonder Woman comme **gardienne du triplet 58** (extension veto-dépense). La cosignature DoD est un acte de **co-sponsorat opérationnel** ; le triplet 58 est un acte de **veto amont**. Les deux peuvent coexister sur le même DoD (Wonder Woman cosignataire DoD + Wonder Woman tenant le triplet 58).

## Le format de triple-signature

### Structure du bloc de signature

```yaml
dod_attention_signature:
  captain_principal:
    name: Superman
    role: Accountable (A) sur le DoD
    responsabilité: cohérence DoD ↔ axes périmètre Growth
  captain_transverse:
    name: <Green Lantern | Flash | Cyborg | Aquaman | Wonder Woman>
    role: Consulted (C) opérationnel OU Accountable (A) double-croisé
    responsabilité: cohérence DoD ↔ périmètre transverse
  captain_qualification:
    name: JohnJones
    role: Consulted (C) sur handoff MQL/SQL
    responsabilité: cohérence DoD ↔ capacité Sales à réceptionner
  signed_at: YYYY-MM-DD
  next_review: YYYY-MM-DD (par défaut 12WY-1 = T-30j)
```

### Double-signature (cas-type 1) — structure réduite

```yaml
dod_attention_signature:
  captain_principal:
    name: Superman
  captain_qualification:
    name: JohnJones
  signed_at: YYYY-MM-DD
  next_review: YYYY-MM-DD
```

**Le bloc captain_transverse est omis** dans la double-signature, pas null — la distinction est significative : Superman Growth doit **explicitement** justifier pourquoi le DoD ne touche pas de capitaine transverse.

## Les 4 asymétries structurelles avec le RACI par rang canonique

### Asymétrie 1 — Superman A sur certaines transitions, C sur d'autres

Le `b2-pair-check-raci-by-rank.md` pose Superman **A** sur les pair-checks #1 (Growth→Sales), #5 (Finance→Growth), #7 (Legal→Growth), et **C** sur les pair-checks #2 (Sales→Ops), #3 (Product→Ops), #4 (Product→IT). Cette distribution est **inversée** par rapport à la triple-signature :

- Triple-signature Superman **A** sur DoD → Superman porte la cohérence globale
- Pair-check RACI **A** sur Superman → Superman porte l'arbitrage de la transition

Les deux **A** ne sont pas équivalents : la triple-signature est **opérationnelle** (qui tient le DoD), le RACI par rang est **structurel** (qui tranche les conflits cross-domaines). Superman peut être **A sur les deux** (cas-types 2 et 3) sans contradiction.

### Asymétrie 2 — Capitaine transverse C ou A selon le DoD

Pour le couple Superman×People (Brand), `brand-raci-asymmetry-canonique.md` pose un **double-A croisé** : Superman A voix + C dotation, People A dotation + C voix. Cette asymétrie est **différente** du pattern triple-signature :

- Triple-signature Superman **A** sur DoD + People **C** sur DoD (par défaut)
- Double-A croisé Superman **A voix** + People **A dotation** (Brand uniquement)

Pour les DoD Brand (cas-type 2 awareness), la triple-signature **doit être interprétée** comme Superman A voix (claim) + People A dotation (ressources brand voice) — c'est le double-A croisé, pas un A+C standard.

### Asymétrie 3 — JohnJones C sur handoff, pas A sur DoD

JohnJones est **C** sur la triple-signature (handoff MQL/SQL), pas **A**. Le DoD attention n'est pas responsable de la qualification Sales — il est responsable de la **pré-qualification** (MQL ou équivalent amont). Si JohnJones veut passer A, il doit transformer le DoD en **pair-check #1 Growth→Sales** explicite avec arbitrage S, (= mode `handoff` B2 Council).

### Asymétrie 4 — Wonder Woman triple vs triplet 58

Wonder Woman apparaît deux fois : comme **capitaine transverse cosignataire DoD** (niveau 5) et comme **gardienne du triplet 58** (veto amont Finance). La cosignature DoD est **subordonnée** au triplet 58 — Wonder Woman ne peut pas cosigner un DoD Growth qui viole le triplet 58. L'amplification bilatérale (`superman-amplification-triplet-58-asymetrie-council-submission.md`) est ce qui **autorise** la cosignature Wonder Woman sur DoD long (SEO).

## Les 4 cas d'application légitime

1. **Brand awareness pre-launch** (cas-type 2 vague 5) — Superman A + People A voix/dotation + JohnJones C.
2. **SEO long-terme** (cas-type 3 vague 5) — Superman A + Flash A contenu + JohnJones C + Wonder Woman C (via triplet 58 amplification).
3. **Co-marketing / partenariats** (cas-type 5 projeté) — Superman A + capitaine transverse variable (Cyborg IT, Aquaman Legal, People Brand) + JohnJones C.
4. **Compliance launch RGPD** (cas-type 6 projeté) — Superman A + Aquaman A conformité + JohnJones C (claim → SQL handoff).

## Les 3 cas d'abus

1. **Triple-signature sans transition cross-domaine** — un DoD 100% Growth qui porte une triple-signature People+Flash+JohnJones est un abus de procédure : Superman demande des cosignatures pour un DoD qui ne touche pas les domaines transverses. Le signal : un DoD sans clause de cohérence transverse (pas de claim → pas People, pas de contenu → pas Flash) ne devrait pas avoir de triple-signature.
2. **Triple-signature sans clause de cohérence à mi-horizon** — un DoD long ou moyen qui porte une triple-signature mais omet la clause de cohérence (cf. `superman-doctrine-roi-horizon-by-growth-channel.md`) viole la doctrine Superman unilatérale.
3. **Triple-signature comme outil politique** — Superman qui exige la triple-signature pour valider un DoD qu'il pourrait tenir seul crée une friction ingérable. Le signal : un DoD qui revient systématiquement en triple-signature alors que sa complexité ne le justifie pas est probablement un abus de position.
