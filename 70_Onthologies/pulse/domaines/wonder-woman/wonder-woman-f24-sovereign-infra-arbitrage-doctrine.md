# F24 Sovereign-infra arbitrage — doctrine isolée et couplage bilatéral Wonder Woman × Cyborg co-signé

## La doctrine F24 — citation verbatim

La doctrine `03_WONDERWOMAN_FINANCE_PRINCIPLES.md` § « Cluster C
F24 » pose verbatim :

> *« **Sovereign-infra arbitrage** drives net margin toward 90%+.
> Chaque fournisseur cloud-only tiers est une **taxe** sur la
> marge nette de l'entreprise. Arbitrer les migrations vers des
> alternatives souveraines (self-hosted, open-source, BaaS
> souverain) est un pouvoir **bilatéral** Finance × IT — Wonder
> Woman calcule la marge rendue, Cyborg tient le chemin de
> sortie documenté. »*

C'est la **seule doctrine F1-F25 qui se projette explicitement
sur un couplage bilatéral entre deux capitaines** (les autres
doctrines F13-F18 sont des visions B1, F19-F22 sont des doctrines
B1/Jerry, F23/F25 sont unilatérales Finance). Le triplet 28 seul
est unaire (veto catalogue) ; F24 ouvre un **couplage explicite**
entre Wonder Woman et Cyborg.

## Le couplage bilatéral Wonder Woman × Cyborg

`wonder-woman-finance-couplings.md` § « Couplage #4 — Finance ←
IT (amont seul, fort) » pose le couplage comme « amont seul » :

> *« F24 ('Sovereign-infra arbitrage drives net margin toward
> 90%+') est **un couplage bilatéral déguisé en amont seul** :
> IT (Cyborg) tient la souveraineté (veto §07), Finance (Wonder
> Woman) calcule la marge nette qui résulte. »*

La doctrine canonique dit explicitement **bilatéral**. Le concept
`finance-couplings.md` dit « bilatéral déguisé en amont seul » —
c'est précisément le **trou** que cette note ferme : F24 n'est
pas « amont seul » ni « aval seul », c'est un **arbitrage
conjoint** où chaque capitaine tient une moitié indissociable de
la décision.

**Concrètement** :

- **Cyborg** tient le **chemin de sortie documenté** (veto §07).
  Pas de chemin de sortie → veto §07 bloque la migration. Pas
  de migration possible sans Cyborg.
- **Wonder Woman** tient la **marge nette rendue** par la
  migration. Si la migration dégrade la marge (coûts de
  migration > économie annuelle), Wonder Woman refuse
  l'arbitrage. Pas de migration rentable sans Wonder Woman.

Les deux **co-signent** la décision de migration. C'est un
**couplage bilatéral symétrique** : pas de dépendance
unilatérale, pas de pouvoir unilateral — la décision exige les
deux capitaines.

## F24 vs F22 vs F25 — distinctions opératoires

Trois doctrines couvrent un terrain adjacent mais **pas le même
périmètre** :

| Doctrine | Question | Capitaine principal | Outil canonique |
|---|---|---|---|
| **F22** « Heavy-asset moat over thin wrappers » | Investir dans un Halo business plutôt qu'un wrapper SaaS ? | Wonder Woman (A unilatéral) | Couplage F22 × Cyborg veto §07 |
| **F24** « Sovereign-infra arbitrage drives net margin toward 90%+ » | Migrer un fournisseur cloud tiers vers une infra souveraine ? | Wonder Woman × Cyborg (co-signe) | Co-signature packet mésoperpétuel |
| **F25** « Plan on the Wright's-law tailwind » | Réinvestir la marge rendue par la déflation software ? | Wonder Woman (doctrine pure) | Aucun outil canonique — modèle économique |

**F22 = décision d'investissement** (avant l'engagement).
**F24 = décision de migration infra** (après l'engagement tiers,
vers une alternative souveraine).
**F25 = réinvestissement post-déflation** (après la migration,
réinvestir la marge rendue).

Ces trois doctrines forment une **chaîne de valeur** :
investir dans un Halo (F22) → migrer l'infra tiers (F24) →
réinvestir la marge rendue par la déflation (F25). La chaîne
doit être tenue conjointement.

## Le veto Cyborg §07 comme garde-fou de F24

Le veto §07 (`b2-eight-domain-vetoes-catalogue.md` § « Les 8
vetos — un par capitaine » ligne 31) est posé verbatim :

> *« **Cyborg** (IT, 05) : Bloque tout **fournisseur cloud-only**
> sans **chemin de sortie documenté**. »*

C'est le **garde-fou amont** de F24 : sans chemin de sortie
documenté, la migration est bloquée par Cyborg, pas par Wonder
Woman. Wonder Woman peut seulement calculer la marge rendue par
une migration **imaginée** — c'est Cyborg qui décide si la
migration est techniquement possible.

**Trois conséquences** :

1. **Cyborg A sur le réalisme technique** (chemin de sortie
   documenté → IaC + plan de réversibilité + failover).
2. **Wonder Woman A sur la rentabilité économique** (marge nette
   rendue > coûts de migration).
3. **Co-signature obligatoire** sur toute décision de migration.
   Aucune des deux parties ne peut imposer la migration seule.

Le `cyborg-triplet-58-amplification-date-reversibilite-council-submission-draft.md`
(tour 3) propose l'amplification « date de revue + métrique de
réversibilité » pour le veto §07. Cette amplification **renforce
le couplage F24** : Wonder Woman peut désormais opposer la même
logique (« date de revue + métrique ») sur la migration, en
parallèle de Cyborg.

## Le scénario type — F24 en pratique

**Situation** (hypothétique, à vérifier en cycle réel) :

- L'entreprise utilise un fournisseur LLM tiers (par exemple
  OpenAI API direct) à $20K/mois.
- Wonder Woman calcule que la marge nette est dégradée de 8 points
  par les fees API (passage de 33% net à 25% net).
- Cyborg propose une migration vers OpenRouter gateway + cache
  sémantique + fallback local Mistral — coût de migration $30K
  one-shot + $4K/mois opérationnel.
- Économie annuelle projetée : ($20K - $4K) × 12 = $192K.
- Payback : $30K / $192K × 12 = 1,9 mois.

**Application F24** :

1. Cyborg tient le chemin de sortie (IaC OpenRouter, plan de
   réversibilité vers OpenAI, failover Mistral). Sans ce
   chemin, F24 ne se déclenche pas.
2. Wonder Woman calcule le payback (1,9 mois) + la marge nette
   projetée post-migration (33% net, retour au floor F4).
3. Les deux **co-signent** un packet mésoperpétuel avec les
   deux décisions positives.
4. Le B3 IT (Kang Dynasty) reçoit le JTBD B3-IT-MIGRATION-OPENAI-TO-OPENROUTER
   avec DoD : IaC + métriques de marge nette rendues + plan de
   réversibilité opérationnelle.

## Le format packet mésoperpétuel F24

Le packet F24 porte, en sus du gabarit standard :

```yaml
meso_decision_id: B2-MESO-DECISION-YYYY-NN
source_mandate: B2-PEER-YYYY-NN
f24_migration:
  source_provider: <fournisseur_tiers_origine>
  target_sovereign: <infra_sovereign_cible>
  migration_capex_eur: <one_shot>
  migration_opex_monthly: <recurrent_post>
  savings_monthly: <delta_mensuel_post_migration>
  payback_months: <capex / savings × 12>
  net_margin_impact_pp: <delta_marge_nette_pp>
f24_migration_co_signed_by:
  finance_captain: wonder_woman  # ou son délégué
  it_captain: cyborg  # ou son délégué
  co_signature_date: 2026-MM-DD
decision: accepted | accepted_conditional | refused
proof_expected:
  - B2 gate finance update (marge_nette_rendue_X_pp)
  - B2 gate IT update (chemin_sortie_documente_IaC_OK)
  - B3 proof path (IT_Kang_Dynasty_migration_executed_with_metrics)
review_cycle:
  - T+30: vérification post-migration capex/opex
  - T+90: vérification marge nette projetée vs réelle
next_review: T+90
```

Le champ **clé** est `f24_migration_co_signed_by` : sans les
deux capitaines signataires, le packet n'est pas Council-ready.
C'est la **trace vérifiable** de la co-signature bilatérale.

## Les 4 cas où F24 est légitime

### Cas 1 — Migration LLM API vers gateway souverain

Situation : OpenAI direct → OpenRouter + cache sémantique +
fallback local. Économie projetée $192K/an. Capex $30K.

- **F24 OUI** : Cyborg tient IaC + réversibilité, Wonder Woman
  tient payback 1,9 mois + marge nette 33%. Co-signature.

### Cas 2 — Migration Supabase vers Postgres self-hosted

Situation : Supabase Cloud $500/mois → Postgres self-hosted sur
Hetzner + dokploy $50/mois. Économie $5,4K/an. Capex $2K
(migration schema + scripts).

- **F24 OUI** : même logique. Réversibilité documentée par
  Cyborg (export schema + scripts de restoration).

### Cas 3 — Migration Vercel → Coolify

Situation : Vercel Pro $20/utilisateur/mois × 5 = $100/mois
versus Coolify $5/mois + maintenance 2h/mois.

- **F24 OUI** : capex 40h × $50/h = $2K. Économie $1,1K/an.
  Payback 22 mois. Marge nette stable. Co-signature.

### Cas 4 — Migration hostinger vers Hetzner

Situation : Hostinger Pro $200/an → Hetzner $50/an + load
balancer. Économie $150/an. Capex $500 (setup + migration
DNS).

- **F24 OUI** : capex > économie année 1 mais break-even à 3,3
  ans. Co-signature sur la base du TCO 5 ans.

## Les 3 cas où F24 serait ABUSIF

### Abus 1 — Migration pour le principe, sans économie

Situation : migration vers une alternative souveraine qui coûte
**plus cher** que le fournisseur tiers (capex + opex
combinés).

- **F24 abusif**. Wonder Woman refuse la migration si le
  payback est >24 mois ou si la marge nette projetée est
  inférieure à la marge nette actuelle.

### Abus 2 — Migration sans chemin de sortie documenté

Situation : Cyborg n'a pas livré l'IaC + le plan de réversibilité.

- **F24 bloqué en amont** par le veto Cyborg §07. Wonder Woman
  n'a même pas à se prononcer — la migration ne se qualifie
  pas comme F24.

### Abus 3 — Migration orchestrée par Wonder Woman seule

Situation : Wonder Woman décide unilatéralement de la migration
sans consulter Cyborg.

- **F24 invalide procéduralement**. F24 est un couplage
  **bilatéral**. Toute décision unilatérale Wonder Woman abuse
  du mécanisme. Le packet doit porter la co-signature des deux
  capitaines.
