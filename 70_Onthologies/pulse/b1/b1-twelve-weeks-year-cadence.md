# B1 twelve-weeks-year cycle — la cadence qui rend B1 vivant

> Le 12WY est la **frequence d'horloge** de l'etage B1. Sans cycle, B1 est un titre dans un organigramme ; avec cycle, c'est un cockpit qui tourne.

## L'origine — E-Myth revisité

Le triplet v3-business explicite la cascade E-Myth telle que Coach OS la porte :

```
B1 Summers (Entrepreneur, 1 rock/mois, 3/12WY)
  --> B2 les 8 VP (Manager, 4 sprints/mois)
    --> B3 les 53 techniciens (Technicien, 5 scrums/semaine)
```

Trois frequences, trois degres de granularite. Le 12WY est **la frequence la plus lente** — c'est normal : c'est l'echelle ou le North Star se teste.

Ces chiffres ne sont pas arbitraires : ils suivent la hierarchie E-Myth (Gerber) ou l'Entrepreneur fixe le cap a 12 semaines, le Manager execute par sprints courts, le Technicien livre par scrums quotidiens. Chaque niveau **divise** la cadence du niveau superieur par un facteur ~4.

## Pourquoi 3 rocks, pas 12

Trois rocks par 12 semaines, c'est **un rock par mois**. C'est la frontiere cognitive : un entrepreneur qui suit plus de 3 rocks simultanement ne suit plus — il subit. La cadence 3/12WY force B1 a **prioriser**, pas a collectionner.

Si B1 veut pousser un quatrieme rock, il doit :
- soit etendre le 12WY (ce qui dilue la responsabilite) ;
- soit remplacer un rock existant (ce qui force le triage) ;
- soit geler un rock (ce qui force le reneg).

Le 12WY tient B1 dans une discipline de **disette oblige**.

## Le rollover — qu'arrive-t-il en fin de cycle

Quatre actions en sequence :

1. **B1 fait le bilan des 3 rocks.** Pour chaque rock : *atteint, partiellement atteint, rate*. La preuve vient de B2 (proof path remontant du B3 JTBD).
2. **B1 renegocie le North Star** si un rock rate revele un drift structurel (ex. : pivot marche US qui ne prend pas, ou la wheel qui reste rouge sur un domaine).
3. **B1 choisit les 3 rocks du 12WY suivant.** Logues dans `01_B1_ROCK_REGISTRY.md` (ou equivalent — le nom exact varie selon les projets).
4. **B1 emet les mandates B2** pour le 12WY suivant. Chaque rock se traduit en un ou plusieurs mandates, addresses aux domaines B2 concernes.

Le rollover est **public** : il tient dans le rapport de fin de cycle, lu par A0 et les gatekeepers.

## La distinction Area (perpetuelle) vs Project (graduée)

Le fractal pose que la 12WY cadence vit a deux deux échelles :

- **Area** (Jerry, perpetuelle) — B1 tourne en 12WY continus. Pas de fin de cycle ; le cycle suivant commence des que le precedent finit.
- **Project** (Summer, daté) — B1 a un 12WY qui **gradue**. Le Project finit (status ACTIVE → COMPLETE → ARCHIVED), et la doctrine qu'il a produite remonte a l'Area.

Cette distinction a une consequence operationnelle : un mandate B1 emis dans un Project a une **fenetre de tir** — le mandat est valide jusqu'a la fin du 12WY du Project. Un mandate B1 emis dans une Area n'a pas de fenetre ; il est valide tant que le North Star ne change pas.

## Anti-pieges

- **B1 qui confond cycle et calendrier.** Le 12WY n'est pas un trimestre fiscal ; c'est un instrument de mesure B1. Si le 12WY devient un calendrier, B1 s'aligne sur les dates plutot que sur la mesure — et la wheel scannee se substitue au succes reel.
- **B1 qui ne rollover pas.** Le 12WY sans rollover est un mensonge : les rocks s'accumulent, l'overdue devient invisible, et la dette d'autorite s'installe.
- **B2 qui cadence en 12WY.** B2 cadence en sprints (4/mois). Si B2 cadence en 12WY, B2 fait le travail de B1, et B1 n'a plus personne pour faire le sien.

## Liens avec le fractal compounds

Quand un Project graduate, les preuves Lead/Lag des Rocks **remontent** a l'Area. C'est le *fractal compounds* : le micro nourrit le macro. Le 12WY Project est l'unite ou cette monteeee se se fait.

Consequence pour B1 : un rock B1 Project qui reussit devient un input Area — la doctrine durcit. Un rock B1 Area n'a pas cette montee ; il teste en continu.
