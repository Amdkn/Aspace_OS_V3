# Shadow L1/L2 Homologie 4-méthodes

> **Thèse centrale** : Shadow L2 (Business) n'est pas un système distinct de Shadow L1 (Life).
> C'est **la même colonne vertébrale à 4 méthodes**, projetée sur des outils cloud/payants
> au lieu d'outils souverains. La matriochka n'a qu'une seule grammaire ; elle change
> d'instrument selon l'étage.

⚠️ Statut Symphony = Shadow A0, **hors-canon SDD, hors-Airlock, sous veto 90j**. V0 =
sable mouvant, PAS en prod. Ce concept documente une homologie observée, il ne ratifie rien.

## 1. L'homologie 4-méthodes (le cœur)

Chaque méthode L1 a un **jumeau L2**, et le rôle ADR-MESH-L2-001 colle exactement :

| Méthode | L1 (souverain) | A2 / Vaisseau | L2 (cloud) | Squad A2 | Rôle MESH |
|---|---|---|---|---|---|
| **PARA** (structure / doctrine) | Obsidian | Enterprise (Picard) | **Notion** | People/Legal (X-Men/Eternals) | **WHAT** — source de vérité |
| **12WY** (objectifs chiffrés) | Baserow | SNW (Curie) | **Airtable** | Growth/Sales/Finance | **HOW MUCH** — quantitatif |
| **GTD** (flux opérationnel) | Plane.so | Cerritos | **ClickUp** | Ops/Product/IT | **WHEN/WHO** — exécution |
| **DEAL** (automatiser / libérer) | Affine | Protostar (Janeway) | *(pas de 4e tracker)* | — | **méta-couche de libération** |

## 2. Pourquoi ce n'est pas une coïncidence

- **Obsidian §10** : *« graduation Notion → Obsidian = migration one-way »* → Notion **est**
  le jumeau cloud d'Obsidian. Tous deux PARA, document-first, WHAT.
- **Baserow** = un Airtable sans frais : Single-Select states, tables structurées,
  colonnes `SLA Max Time/Cost`. Même grammaire que l'Airtable 🦸.
- **Plane ↔ ClickUp** = deux trackers d'issues à state-machine. Plane est le ClickUp souverain.

## 3. Pourquoi L2 a 3 trackers et L1 en a 4

Parce que **DEAL n'est pas un tracker — c'est la méta-couche de libération**, partagée par
les deux étages. Affine (mode Edgeless) produit des Blueprints que Ryan (L0 / 13ᵉ Docteur)
code en connecteurs souverains.

> Conséquence directe : **les `WORKFLOW.*.draft.md` de Symphony SONT des artefacts DEAL.**

Le 4ᵉ tracker du L2 n'est donc pas un outil SaaS de plus : **c'est Symphony lui-même**.
DEAL/Affine schématise → WORKFLOW.md matérialise → Rick souverainise. La pyramide se referme.

## 4. Le pont vertical L1↔L2 (spécifié à 80 %)

1. Baserow `Layer Tag` = `Rock L2` (table « The 12 Rocks »). Un objectif Business est un
   Rock taggé L2, avec `Linked Plane Tickets` + colonnes SLA.
2. Warp Core ratio 50/30/20 : « Top 3 Mon-Tue-Wed = 3 Commitments L2 (50 %) ». Le Business
   reçoit **la majorité** de l'engagement hebdomadaire.
3. Obsidian Areas = 8 Domaines Roue de Vie + 8 Domaines Business (prompt §3).
4. MANIFEST `rock_baserow:` relie chaque projet PARA à son Rock 12WY.
5. Lexique interdit vertical partagé : `innover / disrupter / synergie` est le
   `forbidden_lexicon_global` partout — **même doctrine de langue, deux étages**.

## 5. Le gap honnête

Le pont **L1→L1** est spécifié (Cycle Plane = Semaine Warp Core Baserow ; projet
complexe Plane → note PARA Obsidian, règle Boimler). Mais **aucun WORKFLOW ne lit un
Rock L2 Baserow pour dispatcher dans le slot Airtable Growth** — le lien vertical
L1↔L2 reste conceptuel (tag `Rock L2`, Areas Business, `rock_baserow`).

**Le seul vrai trou** : la matriochka est dessinée, pas encore branchée bout-à-bout.

## 6. Frontières (non négociables)

- Symphony lit, l'agent écrit. Pas de bi-sync, pas d'auto-création de records.
- L2 = `read_only` par défaut ; write uniquement sur Build Gate + sign-off A0.
- Un datum = un propriétaire. Si dupliqué = pointeur (URL/ID), jamais copie.
- Pas d'ADR pour Symphony tant que veto 90j actif. Ce concept est mémoire, pas loi.
