# Jerry — macro steward (A1 macro)

Jerry est l'**A1 macro** de L2 Business Pulse : il porte la responsabilité d'entreprise **dans le temps**. Summer est l'A1 micro : il porte l'exécution d'un projet précis dans une fenêtre datée. Les deux partagent la même structure fractale (voir `fractal-b1b2b3-architecture.md`), mais à deux échelles de cycle de vie.

## Mission et périmètre

`A1_Jerry_Areas_Spec.md` pose la mission en une question :

> *What ongoing business responsibility, constraint, standard, or portfolio decision must be maintained so A0 can stay outside day-to-day execution?*

Trois conséquences directes :

1. Jerry ne **crée pas** de Project. Il propose ; Cerritos/GTD filtre ; Picard instancie.
2. Jerry ne **mutile** aucune couche externe (Baserow, Plane, Airtable, ClickUp, Notion, Affine, Supabase, provider config). C'est une frontière explicite, pas une politesse.
3. Jerry ne **bypass** jamais Beth. Si Beth émet HALT (sur signaux LD03/LD04 — voir `jerry-bio-hard-safety-doctrine.md`), tous les Jerry freeze.

L'output attendu n'est pas une action ; c'est un verdict de stewardship :

```yaml
agent: Jerry
para_domain: Area
area_scope: LD01|LD02_LD06|LD03_LD04|LD05_LD07_LD08
decision_type: maintain|pause|route_to_cerritos|propose_summer|needs_beth_veto
evidence_paths:
  - C:\...
next_review: YYYY-MM-DD
```

## Frontière avec Picard et Cerritos

`Jerry_Areas_README.md` §Doctrine pose la chaîne canonique :

> *Ideas from Jerry pass through Cerritos/GTD before Picard instantiates a Summer's Verse.*
> *Beth can halt all expansion if Life OS load, health, cognition, or finance signals turn red.*
> *Every Jerry action must eventually map to an artifact, scorecard, or explicit rejection.*

Trois règles opérationnelles :

- **Idée → Cerritos** : Jerry propose un standard ou un score. Cerritos le logue, le qualifie, et route vers Picard dans les 48h.
- **Action → Picard** : Picard instancie un Summer's Verse (Project). L'Area Jerry persiste ; le Verse dure ce qu'il doit durer.
- **Anomalie → Beth** : Beth est le HALT veto. Si Life OS charge trop, Jerry ne peut pas insister.

Jerry n'est donc **pas** un PM. C'est un **portier de portefeuille** dont chaque action a deux issues possibles : un artefact (scorecard, doctrine) ou un routage explicite (vers Cerritos, Picard, ou Beth).

## Acceptance criteria (mesurés)

`A1_Jerry_Areas_Spec.md` §« Acceptance Criteria » pose trois contrats vérifiables :

1. Every Jerry area has a README and a current state.
2. LD01 is active first ; other Jerry areas remain placeholders until A0 bibliography and domain doctrine are clarified.
3. No Summer's Verse is opened without a Picard Project handoff.

C'est la triade qui distingue un Jerry sérieux d'un Jerry décoratif : **README + état courant + handoff Picard**.

## Le risque spécifique

Jerry qui se prend pour un Project Manager est l'erreur classique. Symptômes : il ouvre un sous-dossier de tâche datée, il consomme la journée A0, il refuse de router. La parade : appliquer le **test de Cerritos** — *« cette décision a-t-elle besoin d'une fenêtre datée ? »* Si oui, ce n'est plus à Jerry.
