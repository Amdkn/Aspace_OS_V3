# Built-to-Sell — softwareliser l'IP du client, pas ses heures

> **Une seule chose à retenir.** Le client passe d'un modèle **vente d'heures** (plafond = 1 coach × 50h/sem × N clients) à un modèle **vente d'un OS franchisable** (multi-clients, Built-to-Sell, exit option). L'OS softwarelise sa méthodologie ; le client garde la propriété intellectuelle et la revente.

## Énoncé canonique

> L'OS ne remplace pas le coach/l'agence/le COO — **il softwarelise ce qu'ils vendaient en heures**. (`7-sequences-franchise-2026-07-08.md` § "Doctrine commune" #2)

## La transformation modèle économique

| Modèle « heures »                | Modèle « franchise Built-to-Sell »            |
|----------------------------------|-----------------------------------------------|
| Plafond = 1 expert × 50h/sem × N clients | Multi-clients parallèles                |
| Risque marge, attrition          | Revenu récurrent + exit option par acquisition |
| Méthode fuit quand l'expert part | Méthode logée dans l'OS, propriété du client |
| Valeur = temps passé             | Valeur = actif logicielisé (revente possible) |

## Trois exemples canoniques

| Séquence   | Modèle heures                | Modèle franchise                                            |
|------------|------------------------------|-------------------------------------------------------------|
| **A1** Coaching C-Suite | 12h/sem de comptes-rendus manuels | « Chef de Cabinet IA » : synthèse qualitative softwarelisée, multi-cohort |
| **B3** Sales Enablement | Heures de formation + audits manuels | « Évaluateur Stage-Aware » : MEDDICC/SPICED dans le CRM client |
| **C1-C2** Fractional COO | Heures de ré-explication SOPs | « SOPs → Skills exécutables » : Skills agentiques par client |

## Le Built-to-Sell comme test de tier

> Built-to-Sell est le critère T3-T5. Si le client ne peut pas revendre l'OS, ce n'est pas T3-T5 — c'est T1-T2 « chasseur de rabais ». (`7-sequences-franchise-2026-07-08.md` § "Doctrine commune" #2)

Autrement dit : **le tier n'est pas choisi par le commercial, il est imposé par le modèle économique**. Un client T1 PME Solo Founder n'a pas la matière noire suffisante pour franchise.

## Les leviers techniques qui rendent Built-to-Sell possible

- **Gravité des données** : la matière noire s'accumule localement ; la base sémantique se densifie ; l'attrition client tombe vers zéro (le coût de switching devient prohibitif).
- **Déterminisme** : Mirofish + CEO-Bench + Gstack (wargame 09 déjà validé 12/12) garantissent que la promesse n'est pas une promesse en l'air.
- **Matière noire sémantique locale = propriété revendable.** Pas un actif du fournisseur ; un actif du client.

## Ce que ce n'est pas

- Pas une « SaaS-isation » du client. C'est l'inverse : le client **possède** l'OS, le fournisseur installe et maintient.
- Pas un « SaaS white-label ». Built-to-Sell = le client peut revendre la stack ; white-label = le client revend la marque sans la propriété.
- Pas un produit sans propriété intellectuelle. Si le client ne peut pas revendre, ce n'est pas Built-to-Sell.

## Conséquence opérationnelle

Un prospect T3-T5 qui hésite sur Built-to-Sell (« je veux juste utiliser l'OS ») **n'est pas T3-T5** : il faut le relire en T2 PME Solo, ou l'écarter. Le filtre est non-négociable.
