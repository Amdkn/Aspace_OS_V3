# CCS-333: Shared AI-Native Capability Fabric

## 1. Canonical Terminology
- **Capability Fabric:** The shared AI-native infrastructure for exposing and projecting capabilities across the OS.
- **Capability Contract:** The canonical definition of intent, input/output schemas, and effect policy.
- **Harness Adapter:** The translation layer between a specific runtime/model and the Capability Fabric.

## 2. Invariants
- A domain capability is defined once but projected across multiple surfaces (MCP, CLI, API, etc.).
- Agent OS owns the shared capability registry and exposure layers.
- Business OS and Life OS own the actual execution logic and business semantics.

## 3. Authority and State Ownership
- **Agent OS** is authoritative for registry enumeration, surface health, and evidence projection.
- **Business OS / Life OS** are authoritative for the domain-specific business rules and tenant policies.

## 4. Inputs / Outputs / Commands / Queries / Events
- **Command:** `RegisterCapability(capability_contract)`
- **Query:** `ListCapabilities(surface_filter)`
- **Event:** `CapabilityExecuted(correlation_id, effect_receipt)`

## 5. Effects / Receipts / UNKNOWN behavior
- Execution must generate an `EffectReceipt` capturing intent, correlation ID, observed effect, and provenance.
- If a capability fails to execute or state is ambiguous, the execution returns `UNKNOWN`.

## 6. Consumers / Repositories / Product Surfaces
- Used by Agent OS components (CLI, MCP server, API).
- Used by Business OS capabilities to register their operations.

## 7. Migration
- Migrates the existing capability abstractions out of the Coach OS product (`30_Business_OS/10_Projects/coach-os-app/src/lib/tooling/`) into a shared `80_Agent-OS/capability_fabric/`.

## 8. Contract Tests and Release Evidence
- Unit tests verifying the registry correctly loads capabilities.
- Tests verifying parity across adapters (CLI, API, MCP).
- Demonstration of one shared capability (`harness_list`) served via multiple surfaces.
