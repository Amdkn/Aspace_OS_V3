# Agent OS Contract (AOS-001)

A-SPEC complements SDD/PRD/ADR/DDD/TDD. It defines the semantic contract that must survive repositories, transports, runtimes and product surfaces. A document alone does not make a spec VERIFIED; consuming implementations must prove it.

## 1. Canonical Terminology

* **Agent OS**: The executable environment orchestrating workflows and managing presence.
* **API Projection Layer**: The external boundary reflecting internal Agent OS state.
* **Runtime Presence**: The active, observable session of the Agent OS indicating its availability and capability.
* **Reconciliation Protocol**: The synchronization mechanism between the local kernel truth and the Supabase cloud projection.
* **Source Sync Fingerprint**: A cryptographic or deterministic hash representing the exact code state, including nested repo/submodule HEADs.
* **EffectReceipt**: Cryptographically verifiable proof of a business state transition.
* **Degraded Mode**: Safe fallback operational states when core components (e.g., Supabase, specific adapters) are unavailable.

## 2. Invariants

* **No-fake-status rule**: `UNKNOWN` is a definitive business state requiring human intervention. It must never be mapped to `FAILED` or a pseudo-success state.
* **Auth Boundary**: No service-role secrets shall ever be exposed in the browser. Browser clients rely entirely on the API Projection Layer using short-lived tokens or designated public roles.
* **Source of Truth**: The local Agent OS Kernel (`uc.db`) acts as the primary truth plane for work execution; Supabase acts as a projection.
* **Typed Receipts**: All transition receipts must conform to the universal `EffectReceipt` contract, shared across frontend, backend, and runtime.

## 3. Authority and State Ownership

* **Agent OS Kernel**: The sole authority for executing workflows and mutating local runtime state.
* **API Projection Layer (Supabase)**: The designated read-replica and remote projection. It owns the global visibility state but defers execution authority to the kernel.
* **Browser/Edge**: Pure projection surfaces with zero authority to invent state without an `EffectReceipt` from the Kernel.

## 4. Inputs / Outputs / Commands / Queries / Events

### 4.1 Write-Path Separation

The Agent OS write path is strictly segregated into distinct capability channels:
* **Intent**: Registration of a desired outcome (`intent.create`).
* **Work**: Scheduling and execution of tasks (`work.dispatch`, `work.complete`).
* **Claim**: Reserving execution rights and claiming authority over a task (`claim.acquire`, `claim.release`).
* **Session**: Management of continuous runtime presence (`session.start`, `session.heartbeat`).
* **Evidence**: Submission and verification of completion receipts (`evidence.commit`).

### 4.2 Runtime Presence Contract

* **Event**: `PresenceHeartbeat` emitted periodically by the local kernel.
* **Payload**: Includes `session_id`, `runtime_id`, `capabilities`, `status` (e.g., `ONLINE`, `DEGRADED`), and the current `Source Sync Fingerprint`.

### 4.3 Realtime Strategy

* **Broadcast**: For global, non-sensitive state updates.
* **Presence**: Handled via Supabase Realtime Presence, asserting active kernel instances.
* **Polling**: Fallback mechanism for Degraded Modes when WebSockets fail.
* **Server Projection**: Eventual consistency guaranteed by the reconciliation protocol.

## 5. Effects / Receipts / UNKNOWN Behavior

### 5.1 Local kernel <-> Supabase reconciliation protocol

The `RoryReconciler` performs idempotent synchronization across four truth planes:
1. Local runtime state.
2. Local `uc.db` (work table).
3. Git / source fingerprint (including nested repo/submodule HEADs).
4. Supabase `aspace` projection.

Conflicts or missing evidence immediately yield a state of `CONFLICT` or `AMBIGUOUS`, respectively, requiring human intervention.

### 5.2 Failure and UNKNOWN Behavior

* The system must emit an explicit `EffectReceipt` with `status: UNKNOWN` when an operation's outcome cannot be deterministically verified.
* An `UNKNOWN` state blocks automated retries unless explicitly overridden by a human operator through an authorized capability command.

## 6. Migration / Versioning / Supersession

* This specification acts as the V1 architectural foundation for Agent OS.
* Replaces previous undocumented or scattered architectural decisions related to Agent OS sync and presence.

## 8. Contract Tests and Release Evidence

A contract transitions from `DRAFT` to `VERIFIED` when:
1. `Amdkn/Agent-OS-Desktop` successfully implements the reconciliation protocol and passes integration tests simulating a nested repo drift.
2. The UI demonstrates proper isolation of the auth boundary (no service-role secrets).
3. Degraded mode tests verify that the system gracefully handles Supabase disconnection without generating fake successes.
