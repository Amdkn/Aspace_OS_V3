La cause racine : quelque chose dans Windows (Update, Credential Manager, politique de sécurité) **réapplique les permissions héritées du parent** sur `config` à chaque session. Le fix unique nivelé au-dessus du problème.

### assistant

Maintenant la persistance. Sur le VPS, lance ces 3 commandes :

```bash
# 1. Crée le guardian script sur le VPS (au cas où)
cat > ~/ssh-acl-guardian.sh << 'EOF'
#!/bin/bash
# A'Space SSH ACL Guardian — runs locally on Windows to prevent Bad permissions
# Call this from a PowerShell shortcut on Windows at logon

# Strip inheritance on .ssh directory
icacls "$env:USERPROFILE\.ssh" /inheritance:r /T 2>/dev/null
# Replace ACL owner-only with propagation
icacls "$env:USERPROFILE\.ssh" /grant:r "AMD-PC\amado:(OI)(CI)(F)" "SYSTEM:(OI)(CI)(F)" "BUILTIN\Administrators:(OI)(CI)(F)" /T 2>/dev/null
# Verify config clean
echo "[A'Space] SSH ACL Guardian — $(date)"
EOF
```

Puis sur **ton Windows local** (PowerShell en mode admin) :

```powershell
# Créer le scheduled task permanent (anti-recurence à chaque login)
schtasks /create /tn "A_Space_SSH_ACL_Guardian" /tr "powershell -ExecutionPolicy Bypass -WindowStyle Hidden -File C:\Users\amado\.antigravity\scripts\ssh-acl-guardian.ps1" /sc onlogon /ru AMD-PC\amado /f
```
