Le domaine 1 est le **noyau méta-OS** : ce qu'on y traite, ce sont les *conditions
d'existence* des autres domaines. Le canon A'Space y est le plus dense : c'est ici que
vivent les fichiers `AGENT.md`, `SOUL.md`, `CLAUDE.md`, et la doctrine **« the harness IS
the agent's body »** (A0, 2026-06-02). Propriétaire canonique : **B2 Green Lantern** (LD06
Family Burnham ↔ LD01 Business), squad **X-Men** avec **Professor X** en lead.

⚠️ **Pollution** : sur 659 fichiers classés en domaine 1, environ 70 % sont du bruit
capté par les mots-clés `rh|process|hiring|leadership|gouvernance` (cooking, ASMR, religion,

## 1. Ce que le corpus dit

### Thèse 1 — Le harness est le corps de l'agent ; SOUL/AGENTS/CLAUDE.md sont l'identité onboardée

Au-delà du Lore (la roster X-Men, l'identité), un principe People est que **the harness IS
the agent's body**. Une capsule A'Space n'est aussi capable que le harness qui l'exécute.
Les deux corps canoniques sont **Claude Code** et **Hermes** (Nous Research), choisis pour
**agnosticisme** (modèle swappable) et **affordability** (GLM 4.7 Flash via OpenRouter,
plan tokens MiniMax). **SOUL.md = identité primaire**, première dans le system prompt.
**AGENTS.md / CLAUDE.md** = règles de zone et contrat d'embarquement.
Sources : `08_People/agent-harnesses-hermes-claude-code.md` (CANONICAL_FROM_A0, 2026-06-02),
`08_People/_INDEX.md` (B2 Green Lantern × B3 X-Men).

### Thèse 2 — Un business = un système qui tourne sans l'owner ; le test : 7 jours off sans warning

Citation fondatrice (Sam Carpenter, *Work the System*) : *« business as a definition implies
that one does not have to show up in order to earn money »*. Test opérationnel : peux-tu
prendre **7 jours off sans warning** ? Si non, tu as un job, pas un business. C'est la
frontière entrepreneur / freelance déguisé. Sans système : (1) le business existe seulement
dans le cerveau du owner (pire endroit), (2) coût mental × plus élevé (pas de process),
(3) impossible de déléguer correctement, (4) output inconsistant.
Sources : `08_People/2026-06-17_deya-build-systems-business-runs-without-you.md`
(Deya, 10:49, 2026-06-17).

### Thèse 3 — DPS = (Frequency + Annoyance + Impact + Simplicity) / 4 : la formule canonique de délégation

**Delegation Priority Score** : brain dump toutes les tâches récurrentes dans une table →
score DPS → sort descending. Priorité = highest DPS = délègue d'abord. Idéal = rôle
*current owner vs ideal owner* (pas forcément toi = première hire). Pattern =
quantification de la priorité de délégation. Une tâche à fort DPS mais ideal owner ≠ toi
est le premier poste à ouvrir.
Sources : `08_People/2026-06-17_deya-build-systems-business-runs-without-you.md`.

### Thèse 4 — Les 5 étapes canoniques d'onboarding d'un nouveau twin A3

Pattern Deya : (1) **Brain dump** tous les process, (2) **Score** avec DPS, (3) Identifier
**current vs ideal owner** (pas forcément toi), (4) **Documenter AVANT** de déléguer
(*video walkthrough > written > decision tree*), (5) **Hire DBM** (Digital Business Manager)
si tu ne veux pas monitorer toi-même. Le job du CEO = optimiser système après système, pas
fire-killer. Cette séquence est aussi le pattern canonique d'onboarding d'un nouveau twin
A3 dans A'Space.
Sources : `08_People/2026-06-17_deya-build-systems-business-runs-without-you.md`.

### Thèse 5 — DBM = Digital Business Manager : monitor process + alerte déviation

Le DBM monitore les process et intervient si déviation. Analogue direct A'Space : **les A3
twins + agents Symphony** monitorent les skills et alertent si déviation. Sister-skills
canoniques : `a3-cerritos-mariner` (capture inbox) + `a3-cerritos-rutherford` (reflect).
C'est la doctrine qui transforme « founder indispensable » en « organisation auto-surveillée ».
Sources : `08_People/2026-06-17_deya-build-systems-business-runs-without-you.md` (DBM canon),
`08_People/_INDEX.md` (sister canon).

### Thèse 6 — Les 6 patterns de Dynamic Workflows Claude Code soignent les 3 maladies du single-context long

Les 4 maladies du single-context long identifiées : **agent laziness** (15 tâches → 7
faites), **self-preference** (la session s'auto-évalue et se sur-note — biais du créateur
jugeant son propre travail), **goal drift** (le détail initial se dissout sous l'auto-
compaction). Le fix : **agents séparés, contextes isolés** (Sonnet 4.6 par défaut), un
problème par fenêtre.

Les 6 patterns : (1) **Classify & Act** (réceptionniste + quarantaine + dédup) ;
(2) **Fan-out & Synthesize** (micro-parts mutuellement exclusives, citations obligatoires) ;
(3) **Adversarial Verification** (3 sceptiques vs rubrique = pseudo-plan, bouche le trou
du self-preference) ; (4) **Generate & Filter** (1000 idées → 3, judge agent ≠ generator) ;
(5) **Tournament** (pair-wise, *5000 CV → bracket*, traçabilité) ; (6) **Loop Until Done**
(≈ `/goal`, work-tree isolé par théorie).

**Stacking** : on empile les patterns. Exemple canonique : fan-out (insights codebase) →
adversarial-verify (réfuter chaque finding) → loop-until-done (jusqu'à clean pass).
Sources : `08_People/resource_claude_dynamic_workflows_6patterns.md` (Anthropic masterclass,
2026-06-03).

### Thèse 7 — AI SOPs : 3 niveaux + Master Prompt + RACI + règle 95 % + SOP-as-micro-app

Tiago Forte (Guest/Acquira) démontre qu'on passe de **6 mois** de création manuelle de
SOP à **quelques minutes** par SOP avec l'IA. Les 3 niveaux : (a) **Niveau 1** = processus
central end-to-end (mois) ; (b) **Niveau 2** = unité départementale ; (c) **Niveau 3** =
guide tactique mono-personne. L'IA descend l'arborescence : tronc → branches → feuilles.

**Master Prompt** = ADN de l'entreprise injecté dans l'IA (UVP, taxonomie, marge brute
cible 80 %, ton de marque, protocole anti-sycophante : « sois sceptique, conteste mes idées »).
**RACI automatique** assigné à chaque étape (Responsible, Accountable, Consulted, Informed).
**Règle 95 %** : « pose-moi des questions de clarification, mais réponds à tes propres
questions, puis attends ma confirmation » — l'opérateur devient éditeur/validateur, pas
rédacteur. **SOP-as-micro-app** : via Claude Artifacts (React/HTML) + v0.dev / Replit /
Lovable, le SOP devient portail vivant cliquable.
Sources : `08_People/Tiago_Forte/resource_ai_sops.md` (note A3 : 9/10),
`08_People/Tiago_Forte/resource_business_runs_itself.md`,
`08_People/Tiago_Forte/resource_notion_second_brain.md`,
`08_People/Tiago_Forte/resource_no_meetings.md`.

### Thèse 9 — Claude Cowork = agentification du Desktop pour non-techniciens

**Claude Cowork** (macOS sandboxé + extension Chrome) = l'équivalent grand public de Claude
Code. Permet à un non-développeur de déplacer des dossiers, lire des fichiers, contrôler
le navigateur. Cas canonique : Shubham donne accès à un dossier Téléchargements avec 4 300
fichiers hétéroclites → Cowork scanne, propose un plan d'action, **ne supprime rien** (junk
→ `uncategorized/`). Révolution game changer pour non-dev, encore limitée par UX instable
+ besoin de supervision humaine (note 7.5/10).
Sources : `08_People/Shubham_Sharma/resource_claude_cowork.md`.

- **No-system vs Master Prompt** : Deya prêche le système (Sam Carpenter) ; Tiago Forte prêche le Master Prompt comme *substitut* au système humain. Le corpus ne tranche pas : Deya est l'idéologie, Tiago Forte l'outillage.
- **Cowork vs Code** : Shubham Sharma oppose Cowork (non-tech, sandboxé) à Code (CLI puissant, dangereux). Le corpus célèbre les deux, mais reconnaît que **Cowork reste supervisé humain obligatoire**.
- **Tiago Forte Building Second Brain (Notion) vs Hermes Workspace (control plane)** : deux visions de la knowledge management, l'une centrée documentation humaine, l'autre centrée orchestration agentique. Pas de synthèse canonique dans le corpus.
- **Dan Martell (scaling SaaS, 28 vidéos Sales) vs Deya (scaling solo via systèmes)** : deux doctrines de croissance, l'une centrée produit, l'autre centrée owner. Le corpus porte les deux sans arbitrer.
