## Findings

### P1 — AppFrame.tsx:73-75, ActiveRender identity NOT stable
```ts
const ActiveRender = active ? function ActiveRender() { return active.render(); } : null;
```
`ActiveRender` is reassigned on every render → new component-type identity each render. React's reconciliation unmounts+remounts whenever **type** changes (key is irrelevant when types differ). So the bug-fix comment claiming `key={active.id}` is sufficient is **wrong**: any AppFrame re-render (isNarrow, theme, manualCollapsed) tears down the section. The wrapper IS needed, but `ActiveRender` should be `useMemo(..., [active])` or hoisted to a stable component to make `key={active.id}` actually preserve identity.

### P2 — useWindowManager.ts:142, drag-loop effect deps
`useEffect` deps `[…, windowPosition, windowSize]` re-create mousemove/mouseup listeners every drag tick. Listeners are re-bound constantly. Use refs for live values or split the effect.

### P2 — AppFrame.tsx:120, suppress lint on voice-intent effect
`react-hooks/exhaustive-deps` disabled; missing `navigateToSection`, `sections`, `consumeSectionIntent`. Functional risk if `sections` shape changes.

### P2 — useVoiceNavigation.ts:100-101, manual ref-mirror
`runCommandRef.current = runCommand` outside any effect; harmless but obscures intent.
