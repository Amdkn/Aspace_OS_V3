### M-1 — Symlink-following TOCTOU on ticket writes
`C:/Users/amado/agent-os/citadel/dlp/redact.py:213-222, 230-231`

```python
def _safe_destination(destination: Path, root: Path) -> Path:

def _write_once_or_same(path: Path, content: str) -> str:

```

`Path.resolve()` follows symlinks at the moment of resolution, but the actual write uses `Path.write_text` which calls `open()` and follows any symlink that was placed after the resolve. Anyone with write access to the ticket root can race the validation by dropping a symlink at the validated path between `resolve()` and `write_text()`. Mitigations:

- open with `os.open(path, O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW)` (POSIX only), or
- open the parent directory's file descriptor first and operate on `openat()` relative to it.

Severity stays MEDIUM because the attacker must already have write access to `loops/artifacts/tickets/` and the suffix whitelist restricts output to `.md`/`.txt`.

### N-1 LOW — `_is_incomplete_secret_tail` is too greedy in the join direction
`C:/Users/amado/agent-os/citadel/dlp/redact.py:81-106, 99-106`

```python

                          "xoxb-", "xoxa-", "xoxp-", "xoxr-", "xoxs-",

...
def _is_incomplete_secret_tail(scan_so_far: str) -> bool:
    tail_match = _TOKEN_SUFFIX.search(scan_so_far)
    ...
    return any(prefix.startswith(tail) or tail.startswith(prefix) for prefix in _SPLIT_SECRET_PREFIXES)
```

The `prefix.startswith(tail)` clause matches any single character that begins a known prefix — `s`, `g`, `x`, `e`, `a`, `A`. If the scan-so-far ends in prose like `"Hello A"` and the next line starts with a token (e.g., `"tomorrow I will..."`), the newline is consumed and the view becomes `"Hello Atomorrow I will..."`. This does NOT cause a security false positive — no pattern will match `"Atomorrow"`, and the output is reconstructed from the original text, so the visible text is unchanged. But it is a correctness regression on edge cases that future tests should pin. Tighten to require `len(tail) >= 3` and `prefix.startswith(tail)` (i.e., tail is a genuine left-prefix), or restrict `prefix.startswith(tail)` to prefixes that are >= 2 chars.
