# Arcade — Fiche (état au 2026-08-04)

## 1. Positionnement

Arcade se présente comme un **« MCP runtime »**, une couche d'infrastructure intermédiaire entre les agents IA et les systèmes externes. Ce n'est ni un simple gateway MCP, ni une plateforme de tools isolée : c'est une **plateforme unifiée d'autorisation, d'outils et de gouvernance** pour agents IA en production. Positionnement marketing interne : « Okta pour agents IA » — runtime qui transforme un agent de démo en produit prêt pour un security review enterprise.
*Sources :* arcadedev.com (homepage, « MCP runtime »), clients affichés : LangChain, Snyk, Relevance AI, Sybill.

## 2. Plan gratuit

- **Free — 0 $/mois** : 2 000 auth events + 2 000 tool calls par mois, hébergé sur Arcade Cloud, support communautaire (Discord, GitHub), **pas de carte bancaire requise**.
- **Team — 25 $/mois + usage** : 0,10 $/auth event et 0,01 $/tool call au-delà.
- **Enterprise** : sur devis, déploiement Cloud/VPC/air-gapped, SSO, RBAC, audit logs.
*Source :* https://www.arcade.dev/pricing (page tarifaire publique, lue 2026-08-04).

## 3. Connecteurs

- **163 serveurs MCP** listés au catalogue (au 2026-08-03, dernière mise à jour de la page docs).
- Catégories : Productivity & Docs, Social & Communication, Entertainment, Developer Tools, Payments & Finance, Search, Sales, Databases, Customer Support.
- Cinq désignations : *Arcade Optimized*, *Arcade Unoptimized*, *Verified*, *Community*, *Auth Provider*.
- **Formats d'auth supportés** : OAuth 2.0 (mention générique) + providers nommés (Google, Microsoft, Slack, GitHub, Salesforce, etc., ~30 listés). **OAuth 2.1, API key, JWT ne sont pas mentionnés explicitement** dans la doc.
- *Sources :* https://docs.arcade.dev/en/resources/integrations, https://docs.arcade.dev/en/references/auth-providers.

## 4. RBAC

**Documenté partiellement.** Les audit logs mentionnent `principal_type` (USER, API_KEY, etc.) et l'appartenance requise à org/projet pour l'accès, mais le **modèle RBAC explicite par rôle/tool** est évoqué surtout côté Enterprise (« SSO, RBAC, audit logs » sur la page pricing). Pas de page publique détaillée de scoping par équipe en accès libre. Le **scoping par utilisateur** est, lui, bien documenté via les auth configs par utilisateur.
*Source :* https://docs.arcade.dev/en/guides/audit-logs, https://www.arcade.dev/pricing.

## 5. Format de configuration des outils

**Standard MCP.** Le SDK Arcade expose des outils via le protocole MCP. L'exportation vers des formats tiers (CSV, JSON Schema autonome) **n'est pas mentionnée** dans la doc publique. Le code source du framework `arcade-mcp` est open source (MIT), donc l'export est techniquement faisable via le code, mais pas un chemin out-of-the-box supporté par la plateforme.
*Sources :* https://github.com/ArcadeAI/arcade-mcp (MIT), https://docs.arcade.dev/en/references/mcp/python/server.

## 6. Couverture MCP

- **Transports côté serveur documentés explicitement** : `stdio` (cité dans `init_options={"transport_type": "stdio"}`) et **HTTP** (mention « stdio or HTTP feeds read_stream/write_stream »).
- **SSE et streamable HTTP** : non explicitement mentionnés dans la page « Server » de la référence Python. Statut : *annonce, non vérifié sur le détail*.
- **Clients MCP supportés** : Cursor, Claude Desktop, Claude Code, VS Code, Microsoft Copilot Studio, GitHub Copilot.
- **Frameworks d'agents** : AG2, CopilotKit, CrewAI, Google ADK, LangChain, Mastra, OpenAI Agents, TanStack AI, Vercel AI SDK, Spring AI SDK.
- **Statistiques revendiquées** : « 7 500+ ready-to-use integrations », « 81 MCP servers », « enterprise-ready actions runtime » (chiffres homepage).
*Source :* https://docs.arcade.dev/en/references/mcp/python/server, https://docs.arcade.dev/en/get-started/mcp-clients.

## 7. Migration vers auto-hébergement

**Arcade supporte officiellement plusieurs modes de déploiement :**
- **Arcade Cloud** (managé).
- **Azure Marketplace** (managed app).
- **AWS** (offre privée).
- **GCP** — annoncé comme « bientôt disponible ».
- **Self-host via Helm** sur Kubernetes (donc open-core déployable on-prem).
- **Hybrid MCP servers** (serveurs MCP dans votre environnement, branchés sur Arcade Cloud).
- **Warp Pipes** : connecter des clients IA externes à un runtime Arcade auto-hébergé.
*Sources :* https://docs.arcade.dev/en/guides/deployment-hosting, https://github.com/ArcadeAI (tous les dépôts principaux sous MIT ou Apache-2.0).

**Verdict lock-in** : open-core bien réel (frameworks sous MIT), MAIS la valeur métier (auth flows, audit, registry) repose sur Arcade Cloud ou sur des binaires auto-hébergés dont la licence du binaire serveur **n'a pas été vérifiée dans la doc publique**. Lock-in modéré : si vous quittez Arcade, vous perdez le runtime d'autorisation, mais vos outils custom peuvent être réimplémentés en MCP pur.

## 8. Télémétrie sortante

**Désactivable, opt-in par défaut, opt-out trivial.**
- Ce qui est collecté en local/self-host : commande invoquée, **compte** des exécutions (pas les noms ni paramètres d'outils), info machine (OS, CLI), durée, erreurs.
- Ce qui n'est PAS collecté en local : noms d'outils, paramètres, variables d'environnement, logs, PII.
- Opt-out : variable d'environnement `ARCADE_USAGE_TRACKING=0` (Bash/Zsh : `export ARCADE_USAGE_TRACKING=0` ; PowerShell : `$env:ARCADE_USAGE_TRACKING=0`).
- Sur Arcade Cloud : `arcade login` et `arcade deploy` lient les usages à l'identité ; télémétrie étendue selon ToS.
*Source :* https://docs.arcade.dev/en/references/mcp/telemetry.
