## Cause identifiée

Ce n’est pas Codex qui s’ouvre automatiquement par défaut : c’est **ton profil Windows PowerShell 5.1** qui le lance.

1. Windows Terminal utilise actuellement comme profil par défaut :
   - **Windows PowerShell 5.1**
   - `powershell.exe`
   - configuré dans `settings.json:7` et `settings.json:35-38`

2. À chaque ouverture, PowerShell charge automatiquement :
   - `C:\Users\amado\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`

3. Dans ce fichier, la déclaration de la fonction `codexm` a été commentée, mais son contenu est resté actif. La ligne 107 est donc exécutée directement au démarrage :

```powershell
& codex -p minimax --dangerously-bypass-approvals-and-sandbox `
  -C 'C:\Users\amado\ASpace_OS_V2' @args
```

L’analyse PowerShell confirme que cette commande est du **code de démarrage global**, et non du code contenu dans une fonction.

## Ce que cette configuration lance

Elle utilise :

```text
C:\Users\amado\ASpace_OS_V2\.codex-m3-lean\config.toml
```

C’est une ancienne configuration **Codex Lean Relay / MiniMax Sovereign** qui active :

- modèle : `MiniMax-M3`
- profil : `minimax`
- raisonnement : `high`
- dossier de travail : `C:\Users\amado\ASpace_OS_V2`
- validation humaine : désactivée
- sandbox : désactivée
- accès système : `danger-full-access`
- recherche web : active
- mémoire et multi-agent : désactivés
- avertissement de plein accès : masqué

Donc chaque nouveau terminal démarre Codex avec **accès complet et sans demander d’autorisation**.

## Pourquoi cela arrive encore

Le profil PowerShell 7 correspondant a déjà été nettoyé :

```text
C:\Users\amado\Documents\PowerShell\Microsoft.PowerShell_profile.ps1
```

Mais Windows Terminal ouvre encore par défaut l’ancien **Windows PowerShell 5.1**, dont le profil contient toujours le bloc orphelin.

## Correction recommandée

Il faut faire les deux actions suivantes :

1. Supprimer ou désactiver les lignes `98-114` du profil Windows PowerShell 5.1.
2. Définir **PowerShell 7** comme profil par défaut dans Windows Terminal.

Ainsi, `codexm` restera une commande volontaire, mais Codex ne s’ouvrira plus automatiquement. Je peux appliquer cette correction sans toucher aux autres alias et configurations du profil.
