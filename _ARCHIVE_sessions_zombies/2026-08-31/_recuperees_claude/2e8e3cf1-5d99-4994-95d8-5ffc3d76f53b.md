## AgentPulse — concrètement

**Le problème résolu** : *"Traces tell you what happened. They don't tell you where to start investigating."*

Quand un système multi-agents (writer + critic + orchestrateur, par ex) se met à déconner en prod, les traces brutes ne disent pas où chercher. AgentPulse **trace le drift en amont dans le graphe d'handoffs** jusqu'au composant qui a réellement changé.

**Cas concret** : "Le critic a 20% de moins de succès. → Pourquoi ? → Parce que le writer a drifté au run 18 après un changement de prompt. → Le fix est dans writer, pas critic." Sans AgentPulse, tu aurais optimisé critic pendant 2 jours pour rien.

### Comment ça marche (3 étapes)

1. **Instrument** — 2 lignes dans ton app Python :
   ```python
   from agentpulse.sdk import instrument
   instrument()  # patche OpenAI + Anthropic SDKs, capture chaque LLM/tool call
   ```
   Ça hook AutoGen et LangChain si présents.

2. **Stocke** — Chaque event écrit dans `db/<projet>.db` (SQLite, fichier plat, pas de serveur).

3. **Analyse** — Calcule métriques, anomalies, drifts, chaînes causales. Trois surfaces lisent les mêmes findings :
   - **Dashboard Flask** — UI web avec DAG, timelines, trends
   - **CLI `today-drift`** — cartes lisibles en terminal
   - **MCP server** — findings dans CC, pour qu'un coding agent investigue

### Les 3 tools MCP que tu as maintenant dans CC

| Tool | Sortie |

| `get_todays_finding` | Drifts actifs, sévérité (high/drift/candidate/watch), confiance, métriques changées |

## AgentPulse et ton architecture visionnaire

Ton setup (Rick + 3 Cores + 3 Compagnons par core) = un **graphe de handoffs multi-agents** — exactement ce qu'AgentPulse est conçu pour observer. Le mapping concret :

| Vision | AgentPulse |
|---|---|

**Le workflow** : tu `instrument()` chaque process Rick/Core/Companion. Chaque appel LLM/tool s'écrit dans `db/<projet>.db`. Quand un Companion dérape, AgentPulse trace le drift en amont : Companion → Core → Rick. Tu vois où le fix doit aller, pas où le symptôme apparaît.

**Limite** : AgentPulse trace les appels SDK **dans le même process Python**. Si Rick/Core/Companions sont dans des process séparés, chacun a besoin de `instrument()` ou d'un client OTLP qui pousse vers la même DB. C'est faisable mais pas trivial.
