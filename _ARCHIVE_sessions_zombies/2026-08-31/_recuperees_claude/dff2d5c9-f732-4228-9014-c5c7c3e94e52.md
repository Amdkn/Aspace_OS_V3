# TACHE A — Le terminal noir qui s'ouvre a chaque demarrage (PRIORITAIRE)

C'est la demande principale de l'utilisateur. Une fenetre `cmd.exe` noire et vide
s'ouvre a chaque ouverture de session et **reste ouverte**.

## Diagnostic deja etabli — NE PAS le refaire

La cause est la tache planifiee **`\Hermes_Gateway`**. Mesures du 2026-08-04 04:59 :

```
PID 4048   cmd.exe /c "C:\Users\amado\AppData\Local\hermes\gateway-service\Hermes_Gateway.cmd"
           parent = svchost (Planificateur de taches)
PID 10816  conhost.exe   <- c'est lui qui dessine la fenetre visible
```

Configuration de la tache :

| Champ | Valeur |
|---|---|
| Trigger | `MSFT_TaskLogonTrigger` |
| Principal.UserId | `amado` |
| Principal.LogonType | **`Interactive`** |
| Principal.RunLevel | `Limited` |
| Settings.Hidden | `False` |
| MultipleInstances | `IgnoreNew` |
| LastTaskResult | `267009` (= tache en cours d'execution, normal) |

Contenu de `Hermes_Gateway.cmd` :

```bat
@echo off
rem Hermes Agent Gateway - Messaging Platform Integration
cd /d C:\Users\amado\AppData\Local\hermes
set "HERMES_HOME=C:\Users\amado\AppData\Local\hermes"
set "PYTHONIOENCODING=utf-8"
set "HERMES_GATEWAY_DETACHED=1"
set "VIRTUAL_ENV=C:\Users\amado\AppData\Local\hermes\hermes-agent\venv"
C:\Users\amado\AppData\Local\hermes\hermes-agent\venv\Scripts\pythonw.exe -m hermes_cli.main gateway run
exit /b 0
```

**Mecanisme exact** : l'action de la tache est un `.cmd`, donc le Planificateur lance
`cmd.exe` pour l'interpreter. En `LogonType=Interactive`, ce `cmd.exe` recoit une console
visible (`conhost.exe`). Comme la derniere commande du script est `pythonw.exe … gateway run`
— un service qui ne rend jamais la main — `cmd.exe` **attend indefiniment** et sa fenetre
reste affichee. L'auteur a bien choisi `pythonw.exe` (Python sans fenetre) pour etre discret ;
c'est le wrapper `cmd` qui trahit.

## PIEGE A EVITER — la fausse solution

**La case « Masque » / `Settings.Hidden = $true` NE MASQUE PAS la fenetre de console.**
Dans le Planificateur de taches Windows, ce reglage masque *la tache dans la liste de la
bibliotheque*, rien d'autre. C'est l'erreur classique. Ne pas la commettre et ne pas
la proposer comme correctif.

## Correctifs valables — en choisir UN, avec justification

**Option 1 — `LogonType = S4U`** (recommandee par defaut)
```powershell
$t = Get-ScheduledTask -TaskName 'Hermes_Gateway'
$p = New-ScheduledTaskPrincipal -UserId 'AMD-PC\amado' -LogonType S4U -RunLevel Limited
Set-ScheduledTask -TaskName 'Hermes_Gateway' -Principal $p
```
La tache s'execute alors hors session interactive : aucune fenetre. S4U ne demande pas de
stocker de mot de passe. **Prerequis** : le compte doit avoir le droit « Ouvrir une session
en tant que tache » (`SeBatchLogonRight`) — le verifier, et si absent, ne pas forcer,
passer a l'option 2.
**Risque** : si le gateway a besoin de la session utilisateur (notifications, presse-papier,
lecteurs reseau mappes), il cassera. Vu qu'il s'agit d'un service qui ecoute sur
`127.0.0.1:8642`, c'est peu probable, mais **il faut le verifier apres bascule** (cf. §
Verification).

**Option 2 — shim VBScript** (si S4U echoue ou casse le gateway)
Creer `C:\Users\amado\AppData\Local\hermes\gateway-service\Hermes_Gateway.vbs` :
```vbs
CreateObject("WScript.Shell").Run """C:\Users\amado\AppData\Local\hermes\gateway-service\Hermes_Gateway.cmd""", 0, False
```
Le `0` est le style de fenetre = masquee, le `False` = ne pas attendre.
Puis pointer l'action de la tache sur `wscript.exe` avec ce `.vbs` en argument.
Conserve exactement la semantique `Interactive`, masque seulement la fenetre.

**Option 3 — appeler `pythonw.exe` directement**, sans `cmd`.
Action = `…\venv\Scripts\pythonw.exe`, arguments = `-m hermes_cli.main gateway run`,
repertoire de travail = `C:\Users\amado\AppData\Local\hermes`.
**Attention** : cette option **perd les 4 variables d'environnement** posees par le `.cmd`
(`HERMES_HOME`, `PYTHONIOENCODING`, `HERMES_GATEWAY_DETACHED`, `VIRTUAL_ENV`). Ne la retenir
que si vous avez verifie dans le code de `hermes_cli` qu'elles sont facultatives.
Le repertoire est `C:\Users\amado\AppData\Local\hermes\hermes-agent\` — lisez-le avant.

## Ce qu'il faut faire

il perd l'acces. **Cette valeur est a proposer, pas a appliquer.**

`Get-NetTCPConnection -State Listen` que 5800 a disparu.
