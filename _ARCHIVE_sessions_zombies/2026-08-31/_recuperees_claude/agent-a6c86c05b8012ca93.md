### Per-app theme resolution (lines 83-92)
```ts
const appId = title.toLowerCase().replace(/[^a-z0-9-]/g, '-');   // "Product" → "product"
const activeThemeId = useThemeIdFor(appId);
const tokens = useThemeStore((s) => s.tokensFor(appId));
useEffect(() => {
  if (rootRef.current) applyThemeTokens(rootRef.current, tokens);
}, [tokens, activeThemeId]);
```
**Key behavior**: tokens are applied as **scoped** CSS variables on `rootRef.current` (the AppFrame's outer `<div>`), NOT on `:root`. This lets each window render with its own design identity — multiple apps can be open simultaneously with different themes.

### How a child app decides which theme
The child does NOT decide. AppFrame derives `appId` from `title`, then the resolution chain is:
1. `useThemeStore.appThemes[appId]` (user-set per-app override)
2. `CANONICAL_APP_THEMES[appId]` (canon default per business domain)
3. `useThemeStore.globalTheme` (user-set global default)

### Theme switching lifecycle (when user picks in Settings → Themes)
