# youtube-takeout-to-lifeos

## When to use

- A0 mentions "YouTube takeout", "watch history", "videos to Geordi", "categorize my videos", "Life OS videos", "transcript", "guide youtube", "capture transcriptions"
- A new `watch-history.html` is in `Downloads/` and A0 wants it processed
- Re-running (idempotency = skip already-categorized)

## When NOT to use

- No `watch-history.html` at the default path → ask A0 for the path or run with `TAKEOUT_PATH=...`
- Per-video deep analysis (this is bulk capture, not 1-by-1 review)
- LLM-summarized guide (this script is mechanical — fetches transcripts + distills head/tail paragraphs, no LLM calls)

## Two modes

| Mode | Script | Output | Per-LDxx cap (default) | When to use |
|---|---|---|---|---|
| **Metadata-only** | `categorize_takeout.py` | .md with frontmatter + placeholder body | 11 | Fast triage, all videos, no transcript |
| **Transcript + guide** | `capture_june_transcripts.py` | .md with frontmatter + key excerpts (head/tail) + full transcript | 10 | When A0 wants the actual content searchable |

Both share `.processed.json` (idempotency), Shorts filter (`#shorts`), categorization (LDxx keywords), and the Geordi 09_Life_OS output path.

The script:

8. Writes per-run summary: `09_Life_OS/.runs/transcripts_<timestamp>.json`

## Idempotency rules (D4 no-self-contradiction)

- `.processed.json` = flat set of `{video_id: {ld, timestamp, file}}` entries
- Re-run on the same takeout → all entries skipped (same IDs in processed set)
- New takeout (different `watch-history.html`) → only NEW video IDs processed
- Delete `.processed.json` → force re-process everything (nuclear option)

## Anti-patterns (D6 root cause)

- ❌ Treating "watch history" as a single block — videos need per-LDxx categorization
- ❌ Assigning all videos to LD04 (tech bias) — keyword scoring prevents this
- ❌ Re-processing the same video on every run — tracked in `.processed.json`
- ❌ Mutating existing Geordi files — script only WRITES new files, never edits
- ❌ Hardcoding paths — env vars `TAKEOUT_PATH`, `START_DATE`, `END_DATE`, `GEORDI_ROOT`
