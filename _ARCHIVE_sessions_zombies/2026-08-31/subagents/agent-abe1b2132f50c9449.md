## Supporting Patterns for PeopleApp.tsx — Distilled Summary

### 1. Reusable UI primitives (`src/apps/_ui/`)

**`CMSCardList.tsx`** (canonical list→grid renderer)
- Generic `CMSCardList<T>` reads `useCmsStore(s => s.items[collectionId])` and maps each item to a `FleetItemCard` via a `render: (item) => ({ title, subtitle, description, statusLabel, statusTone, accent, icon, metricLabel, metricValue, meta })` function.
- Accepts `onOpen?: (id: string) => void`, `cols?: 1|2|3`, `emptyMessage`. Call `onOpen(id)` to navigate into a detail — typically wired to `drill.open(id)`.
- Pattern: import → `<CMSCardList<TypedItem> collectionId="…" onOpen={drill.open} render={item => ({...})} />`.
- Shows an empty-state line when `items.length === 0`.

**`FleetItemCard.tsx`** — clickable rounded card with avatar/icon, title, subtitle, status pill, description (2-line clamp), and a metric+meta footer. Always wrapped in a `<button>` when `onClick` is set (chevron trailing). `FleetItemGrid` is the responsive 1/2/3-col wrapper.

**`kit.tsx`** — `AppShell`, `StatCard`, `Card`, `Badge`, `PrimaryButton`, `GhostButton`, `ScoreBar`. All use CSS variables (`var(--theme-accent)`, `var(--panel-border)`) and Tailwind neutrals (`stone-*`, `green-*`, `amber-*`, `red-*`). No app-specific colors.

**`widgets.tsx`** — `Avatar`, `Dot`, `Toggle`, `ProgressRow`, `KanbanBoard`/`KanbanCard`, `Table`, `FunnelStep`. Same convention: theme vars + neutrals.

### 3. Card → Detail navigation (canonical pattern)

There is **no `registerItemDetail` function** in the codebase — that name does not appear. The actual pattern is:
- `useCollectionDrill(collectionId, sectionLabels)` (in `src/hooks/useCollectionDrill.ts:10-47`) returns `{ openId, open, close }`. Pass one or more section labels (string or array) — the hook resets to the list view whenever the active section changes.
- In each section render: `if (drill.openId) return <DynamicPageView collectionId="…" itemId={drill.openId} onBack={drill.close} onNavigate={drill.open} />;`
- The hook auto-pushes a breadcrumb via `setDetail({ label, onBack: close })` (lines 38-40), and AppFrame consumes it on section switch (`AppFrame.tsx:67-72`).
- `DynamicPageView` (`src/components/cms/DynamicPageView.tsx`) is the **single shared detail template** for every CMS collection — accent from `def.accent`, hero field = first number/currency, grid = remaining non-longtext, prose = longtext. Includes prev/next navigation.
- **Cards navigate via `onClick={() => drill.open(String(item.id))}`** — that single call triggers both `setDetail` (breadcrumb) and the `DynamicPageView` swap.

### 4. useCmsStore API (`src/lib/cms/cms.store.ts`)

Shape: `collections: Record<collectionId, CmsCollectionDef>` and `items: Record<collectionId, CmsItem[]>`. APIs:
- `s.collections[id]`, `s.items[id]` (subscribed reads)
- `registerCollection(def, seedItems)` — idempotent (HMR-safe), wired to live Supabase hydration
- `updateItem(collectionId, id, patch)`
- Module-level `getCollectionDef(id)`, `getCollectionItems(id)`

`CmsItem` is `{ id: string; [key: string]: unknown }`. `CmsCollectionDef` (`src/lib/cms/types.ts:19-32`) has `id`, `name`, `singular`, `accent`, `titleField`, `subtitleField?`, `badgeField?`, `fields: CmsField[]` where `CmsField.type` is `'text' | 'longtext' | 'badge' | 'date' | 'currency' | 'number'`.

### 5. Seed conventions (`src/lib/cms/seed.ts`)

Pattern is per-collection: a `def(...)` for the definition, a typed `items: CmsItem[]` array, then `useCmsStore.getState().registerCollection(xDef, xItems)` inside `seedCms()` (lines 470-497). **People already has two seed collections registered** (lines 59-91): `team` (id `'team'`, accent `'#0891b2'`, fields: role/focus/status/bio, 6 X-Men items) and `people_agents` (id `'people_agents'`, same accent, 2 items). New sections that want CMS-driven cards can either reuse these or add new collections following the same shape.
