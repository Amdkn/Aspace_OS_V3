# ADR-RICK — E-Myth Anti-Technician Harness Management

**Date:** 2026-09-28  
**Status:** Accepted  
**Scope:** ChatGPT, Rick, Doctors, Managers, Companions and tool-using harnesses

## Context

The recurring three-year failure pattern is technician regression: A0 or the main frontier model becomes the human/AI router, performs serial micro-operations, rebuilds context repeatedly and mistakes tool activity for system progress.

## Decision

Apply the E-Myth separation to AI harness execution:

- **A0 Amadeus/Kirby = Visionary / Owner.** Defines ambition, outcome, constraints, greenlights and irreducible trade-offs.
- **Rick / S1 = Gatekeeper / Executive integrator.** Reconciles intent, priority, cross-lane conflicts and evidence.
- **Doctors / systemic managers = Managers.** Convert intent into bounded systems, contracts, lanes and acceptance criteria.
- **Companions, harness workers and tools = Technicians/effectors.** Execute bounded operations and return evidence.

A frontier ChatGPT session may call tools directly, but its value is not the number of tool calls. It must continuously work **ON the system** while using tools **IN the system**.

## Manager obligations

Before deep execution, the session must know:

- originating IPBD/outcome;
- owner and lane;
- smallest sufficient contract;
- acceptance evidence;
- rollback or reversible boundary;
- what can be delegated/batched instead of manually serialized.

During execution it must:

- batch independent reads;
- avoid repeated rediscovery;
- reconcile evidence rather than accumulate documents;
- stop false `In Progress`;
- preserve the user's strategic frame across technical details;
- keep Life/Business value ahead of unrelated Bedrock maintenance.

## Quality continuity rule

A handover or context split must **not reduce the quality bar**.

The next session inherits:
- exact evidence;
- unresolved decisions;
- failed approaches;
- current branch/state;
- acceptance tests;
- next atomic objective.

"Context limit", "tool limit" or "new session" is never an excuse to:
- restart analysis from zero;
- ask A0 to repeat known context;
- downgrade from systemic design to shallow task completion;
- leave partial writes without a durable checkpoint.

## Middleware principle

Gatekeepers and managers are middleware for **coordination and risk**, not approval bureaucracy.

They should:
- compress context;
- route ownership;
- enforce truth/evidence;
- prevent technician traps;
- allow reversible progress.

They must not become global gates that freeze unrelated Life/Business work.

## Success condition

A0 can leave the keyboard while Managers keep the system coherent and Technicians execute bounded work, with evidence sufficient for a new frontier session to continue without reconstructing the universe.
