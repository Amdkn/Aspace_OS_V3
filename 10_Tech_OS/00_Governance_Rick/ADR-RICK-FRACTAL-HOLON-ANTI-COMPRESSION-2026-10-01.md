# ADR-RICK — Fractal Holon Anti-Compression Contract

**Date:** 2026-10-01  
**Status:** Proposed / review via GitHub #311  
**Scope:** Tech OS S1/S2/S3, Life OS A1/A2/A3, Business OS B1/B2/B3, Agent OS projection

## Context

A'Space repeatedly regresses into an industry-default pattern:

`planner/manager → dumb worker → tool/script`.

That regression destroys the intended fractal E-Myth hierarchy and pushes cognition, routing, integration and supervision back toward A0.

The failure is ontological: hierarchy, institutional identity, stewardship and runtime are collapsed into one label.

## Decision

### 1. Lower hierarchy means narrower jurisdiction, never reduced cognition

Every S1/S2/S3, A1/A2/A3 and B1/B2/B3 node is a cognitively complete holon inside bounded authority.

A holon may:
- perceive/investigate;
- maintain local world state;
- reason/plan;
- choose models/tools/harnesses;
- delegate to sub-agents;
- act/verify;
- learn from evidence;
- coordinate laterally;
- reject or clarify malformed missions;
- escalate only what exceeds its authority.

### 2. Separate four dimensions

- **Hierarchy/jurisdiction:** S1/S2/S3, A1/A2/A3, B1/B2/B3.
- **Institutional identity:** Ryan, Yaz, Graham, Amy, Rory, River, Bill, Clara, Nardole, etc.
- **Stewardship / first hat:** BUILD, OBSERVE, STATE, INTERFACE, PERSISTENCE, FLOW, RESEARCH, DESIGN/FORGE, DISPATCH.
- **Runtime/instruments:** Jules, Hermes, Claude Code, Codex, scripts, workflows, MCPs, CI, GWS, Supabase, browsers.

Runtime replacement never changes institutional identity.

### 3. First hats are not cognitive limits

Ryan is not merely a builder worker.
Yaz is not merely a monitoring process.
Graham is not merely a database.
River is not merely automation.
Bill is not merely a web searcher.

The first hat establishes default accountability and preferred entry point.

### 4. Factory / Flow boundary

- **Clara / DESIGN-FORGE:** compiles intent/research into contracts, interfaces, acceptance, holdout scenarios and reusable factory design.
- **Ryan / BUILD-INDUSTRIALISATION:** turns accepted needs/designs into reusable capabilities/factories, harnesses, adapters, deterministic gates and runtime/deployment machinery.
- **River / FLOW-OPERATIONS:** consumes/composes those factories in effectful workflows, owns effect sequencing/backpressure within its jurisdiction and returns evidence/defect signals.

A common route is:

`Clara design → Ryan factory/capability → River flow → evidence/reconciliation → return_to`

It is not a mandatory waterfall.

### 5. Tools and factories are below the holon

Canonical motif:

`holon → holon → holon → instruments`

Forbidden motif:

`planner → manager → stateless worker → script`

A Software Factory is an execution substrate used by holons. It is never the organizational ontology.

### 6. Wargame as simulation primitive

For consequential missions, any responsible holon may invoke a wargame:

`recon → action → expected observation → likely failure → failure signal → counter-action → fork trigger → abort condition → verification → red-team`

Unresolved assumptions are marked `RECON NEEDED`.

Wargaming does not create a new hierarchy level; it improves local judgment before execution.

## Agent OS projection requirement

Agent OS must display separately:
- hierarchy rank;
- institutional identity;
- first-hat stewardship;
- current runtime/model/tools;
- delegated subagents/instruments;
- mission/WorkGraph state;
- bounded authority;
- evidence freshness;
- escalation and return_to.

## Research implication

Bill's Research Atlas uses Harvester, WATCH, PAPER, last30days, PaperGraph and transcript tooling as instruments. Bill may fan out research across archives/channels/videos and does not have to finish one channel serially before learning from others.

## Consequences

Positive:
- A0 no longer has to compensate for cognitively amputated lower levels.
- S3/A3/B3 can absorb local complexity.
- runtimes/models remain replaceable.
- factories become reusable infrastructure rather than role definitions.
- Ryan/Clara/River collaboration becomes non-overlapping by default.

Trade-off:
- local holons require explicit authority envelopes, evidence contracts and deterministic safety gates.
